# Internal Linking Plan

Updated 27 Sep 2026: sectors now match the five portfolio groups; see src/content/sectors.ts.

**Model:** hub-and-spoke with silo discipline. Authority flows from the homepage to three hubs:

- `/investments/` (commercial)
- `/invest-nepal/` (informational pillar)
- `/sectors/` (category: Education Consultancy, College, Energy Sector, Property Development, Financial Channel)

From the hubs it flows to their spokes. Outer-section articles link _back up_ into core pages through contextual bridges. `/portfolio/` mirrors the five sectors with in-page anchors (`#education-consultancy`, `#college`, `#energy`, `#property-development`, `#financial-channel`).

Anchor text is descriptive and matches the target page's topic (no "click here"). Each target is linked **once per section** at most. `scripts/seo-audit.mjs` verifies there are no orphans and no broken links. Old sector URLs are 301 redirects (`config/http-rules.mjs`); never link to them.

## 3. Link rules for new content

1. Every new insight must link to **one core page** (project, sector or `/investments/`) using an anchor that matches that page's topic, and to **its pillar** (`/invest-nepal/` or its sector).
2. Every new project page must be linked from `/investments/` (automatic), its sector page (automatic), the homepage current-project block when `featured: true` (automatic), and at least one insight.
3. Project updates link to their project, and the project page lists them (automatic via `updates`).
4. Don't link the same target twice in one section. Don't use "click here" or "read more" without context (cards use the article title as the link text).
5. External links to official sources use `rel="noopener"` and open in a new tab with a screen-reader notice.
6. Link to the current sector URLs only: `/sectors/education-consultancy/`, `/sectors/college/`, `/sectors/energy/`, `/sectors/property-development/`, `/sectors/financial-channel/`.
